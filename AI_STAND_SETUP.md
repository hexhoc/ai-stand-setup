# Подготовка проекта 1С для AI-разработки

## Цель

Подготовь XML-проект 1С:Предприятие 8.3 для работы с OpenCode V2 на Windows.

Настрой:
- Skills для 1С и БСП.
- Правила и команды OpenCode.
- XML-исходники конфигурации и расширений.
- Git и `AGENTS.md`.
- MCP BSL Language Server.
- YAxUnit и `tests` — при необходимости.

## 1. Общие правила

1. Работай из корня проекта, если не указан другой каталог.
2. Перед изменениями изучай текущее состояние. Корректные компоненты не трогай.
3. Сохраняй пользовательские файлы, настройки и историю Git.
4. Для управляемых файлов используй manifest, SHA-256 и атомарную запись. Не перезаписывай пользовательские изменения.
5. Вспомогательные репозитории размещай во временных каталогах. Удаляй только созданное текущим запуском.
6. Не выполняй `git reset --hard`, `git clean`, `git checkout --`.
7. Не сохраняй секреты и локальные реквизиты информационных баз в Git.
8. Все решения и разрешения получай по процедуре раздела 3.
9. Выполняй только согласованные операции. При ошибке продолжай независимые этапы.
10. Не создавай и не запускай тесты в процессе подготовки.
11. Если на любом из шагов возникли сложности или ошибки, не решай их самостоятельно, согласуй решение.

## 2. Диагностика проекта

Выполни только операции чтения.

### 2.1. Окружение

Определи абсолютный путь проекта и проверь:
- Windows PowerShell 5.1+;
- Git — `git --version`;
- Python 3 — `python --version`;
- OpenCode V2 — `opencode --version`;
- платформу 1С 8.3;
- доступность GitHub.

### 2.2. Существующие компоненты

Определи:
- Состояние Git и наличие истории коммитов.
- Установленные skills, правила и команды OpenCode.
- Наличие `AGENTS.md`, `opencode.jsonc`, `.v8-project.json`.
- XML-конфигурации, расширения, их имена и версии.
- Доступные информационные базы.
- Наличие и версии YAxUnit и `tests`.
- Наличие и версию BSL Language Server.

Рекурсивно найди `Configuration.xml`, исключив `.git`, `.opencode`, `tools`, `build` и временные каталоги.

Классифицируй XML с учётом namespace:
- нет `ConfigurationExtensionPurpose` — основная конфигурация;
- есть `ConfigurationExtensionPurpose` — расширение.

### 2.3. План изменений

На основании диагностики составь перечень:
- Уже готовых компонентов.
- Необходимых установок и обновлений.
- Недостающих XML-исходников.
- Операций с информационными базами.
- Пользовательских файлов, требующих изменения.
- Необязательных компонентов.

Не изменяй проект до завершения согласования.

## 3. Единое согласование

После диагностики **одним запросом** получи все необходимые решения.

| Область                | Что согласовать                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| Конфигурация           | Выбор основной конфигурации при нескольких вариантах; `configAlias` при его отсутствии           |
| Разработка             | Разрешены ли изменения основной конфигурации или только расширений                               |
| Информационная база    | Выбор базы и недостающие реквизиты подключения                                                   |
| XML                    | Конкретные непустые каталоги, выгрузки в которых потребуется заменить                            |
| Расширения             | Какие прикладные расширения выгружать в Git                                                      |
| Тестирование           | Нужен ли YAxUnit и расширение `tests`                                                            |
| Тестовая база          | Выбор dev/test базы, подтверждение её непродуктивного назначения и допустимости изменений        |
| Изменения базы         | Перечень загрузок, обновлений, изменений свойств расширений и допустимых операций восстановления |
| Инструменты            | Какие установленные программы разрешено обновить; путь установки BSL Language Server (по умолчанию `C:\bsl-language-server`)            |
| Git                    | Разрешение на первый коммит, если существующий репозиторий не имеет истории                      |
| Существующий AGENTS.md | Заменить или обновить |

### Порядок согласования

1. Показывай только вопросы, требующие решения.
2. Для каждого потенциально опасного действия указывай конкретный объект и ожидаемое изменение.
3. Предлагай значения по умолчанию, когда они однозначно определяются диагностикой.
4. Пользователь может разрешить или отклонить каждую необязательную операцию независимо.
5. Зафиксируй утверждённый план и выполняй его без повторного согласования.
6. Если обнаружилась новая операция за пределами утверждённого плана, согласуй только её.
7. Отказ или отсутствие разрешения блокирует соответствующую операцию, но не остальные этапы.

## 4. Установка skills и правил

### 4.1. Skills 1С

Источник: `https://github.com/Nikolay-Shirokov/cc-1c-skills`

1. Клонируй репозиторий во временный каталог.
2. Зафиксируй commit SHA.
3. Выполни `python scripts/switch.py opencode --project-dir <ProjectRoot>`.
4. Удали временный checkout.

При повторном запуске используй тот же механизм обновления.

Ожидаемые файлы:
- `.opencode/skills/.cc-1c-skills.json`
- `.opencode/skills/db-dump-xml/SKILL.md`
- `.opencode/skills/cfe-init/SKILL.md`

Для последующих операций используй соответствующие локальные `SKILL.md` и штатные скрипты.

### 4.2. Skill БСП

Источник: `https://raw.githubusercontent.com/brake71/1c-ssl-skills/main/install.ps1`

Скачай установщик во временный файл и выполни с параметрами:

`-Agent OpenCode -Target ./.opencode/skills`

Ожидаемый файл: `.opencode/skills/bsp/SKILL.md`.

### 4.3. Правила и команды

Источник: `https://github.com/hexhoc/onec-ai-ready-setup`

1. Клонируй репозиторий во временный каталог.
2. Зафиксируй commit SHA.
3. Найди полный комплект исходной инструкции:
   - `content/manifest.json`
   - `content/rules/`
   - `content/commands/`
   - `AGENTS-TEMPLATE.md`
   - `content/manifest.json`
Если комплект недоступен, отметь зависимый этап как ожидающий пользователя.
4. Установи:
   - `content/rules/*.md` → `.opencode/rules/`
   - `content/commands/*.md` → `.opencode/commands/`
   - `AGENTS-TEMPLATE.md` → `AGENTS.md`. Замена или обновление существующего зависит от согласования

5. Храни версию manifest `content/manifest.json`, пути и SHA-256 управляемых файлов в `.opencode/.dev-agent-content.json`.

6. Не подключай все правила глобально через `instructions`. Используй условную маршрутизацию в `AGENTS.md`.

7. Удали временный checkout


## 5. Подготовка XML-исходников

Целевая структура:

```text
<configAlias>/
  src/
    Configuration.xml

<configAlias>.<ExtensionName>/
  src/
    Configuration.xml
```

Требования:
- `configAlias`: `^[a-z][a-z0-9-]*$`;
- `ExtensionName` точно совпадает с XML-свойством `Name`;
- регистр и кириллица имени расширения сохраняются;
- существующие каталоги автоматически не переименовываются.

### 5.1. Реестр баз

Используй `.opencode/skills/db-list/SKILL.md`.

Создай или актуализируй `.v8-project.json`:

- `v8path` — путь к платформе;
- `databases[].id` — уникальный ID;
- `databases[].configSrc` — путь к XML основной конфигурации;
- `databases[].extensions[]` — расширения и их XML-пути;
- `default` — база по умолчанию.

Сохраняй существующие записи.

### 5.2. Основная конфигурация

Если XML отсутствует:

1. Выгрузи через `db-dump-xml -Mode Full` в `<configAlias>/src`.
2. Получи код возврата и лог Конфигуратора.
3. Выполни `cf-validate`.

### 5.3. Прикладные расширения

Если утверждена выгрузка:

1. Получи список через `db-cfe-admin list`.
2. Выгрузи выбранные расширения через `db-dump-xml -Mode Full -Extension "<Name>"`.
3. Выполни `cfe-validate` с основной конфигурацией.

Служебные расширения автоматически не выгружай.

## 6. Настройка YAxUnit

Выполняй раздел только при выборе тестового контура.

### 6.1. YAxUnit

Определи состояние расширения:

- Версия подходит — используй её.
- Есть только в базе — выгрузи XML.
- Есть только в XML — загрузи в базу.
- Требуется установка или обновление — получи стабильный релиз через `https://api.github.com/repos/bia-technologies/yaxunit/releases/latest`.

Для установки:

1. Скачай `YAxUnit-<version>.cfe` в `build/yaxunit/`.
2. Проверь совместимость и доступную контрольную сумму.
3. Выполни `db-load-cf`.
4. Примени через `db-update -Extension YAxUnit`.
5. Выгрузи XML в `<configAlias>.YAxUnit/src`.

Не понижай установленную версию.

### 6.2. Расширение tests

Если отсутствует, создай через `cfe-init`:

| Параметр | Значение |
|---|---|
| Name | `tests` |
| Synonym | `Тесты` |
| NamePrefix | `tests_` |
| Purpose | `AddOn` |
| ConfigPath | Основная конфигурация |
| OutputDir | `<configAlias>.tests/src` |

Загрузи через `db-load-xml -Extension tests` и примени через `db-update -Extension tests`.

Для `YAxUnit` и `tests` отключи:
- Безопасный режим.
- Защиту от опасных действий.
- Использование основных ролей для всех пользователей.

Используй `db-cfe-admin set-properties` для поддерживаемых параметров. Недоступные изменения внеси в список ручных действий.

### 6.3. Тестовая база

Для утверждённой dev/test базы:

1. Назначь уникальный alias `yaxunit-test`.
2. Добавь XML-сопоставления `YAxUnit` и `tests`.
3. Сохрани остальные расширения и параметры базы.

Операции восстановления ограничь утверждённым перечнем из `AGENTS-TEMPLATE.md`.

Последующий запуск тестов — через `/yaxunit-test` по отдельному запросу.

## 7. Настройка Git

Если `.git` отсутствует, выполни `git init`.

### .gitattributes

Добавь правила исходного комплекта:
- `* text=auto eol=lf`;
- XML, BSL, JSON, Markdown и скрипты — LF;
- изображения, архивы и бинарные файлы 1С — `binary`.

### .gitignore

Обеспечь наличие:

```gitignore
/.opencode/
/.metadata/
/.v8-project.json
/build/
opencode.jsonc
```

Дополнительно исключи каждый `ConfigDumpInfo.xml` по точному относительному пути.

Коммит выполняй после финальной проверки по условиям раздела 10.

## 8. Настройка MCP BSL Language Server

Если сервер отсутствует или обновление утверждено:

1. Получи релиз через `https://api.github.com/repos/1c-syntax/bsl-language-server/releases/latest`.
2. Скачай `bsl-language-server_win.zip`.
3. Проверь доступную SHA-256.
4. Распакуй полный архив во временный каталог.
5. Проверь EXE через `--help` или `--version`.
6. Перемести поставку в согласованный каталог.

Настрой корневой `opencode.jsonc`:

```text
$schema = https://opencode.ai/config.json

mcp.servers.bsl-language-server:
  type = local
  command = [
    <absolute-path-to-exe>,
    "mcp",
    "--protocol",
    "stdio"
  ]
  cwd = "."
  timeout.startup = 120000
  timeout.catalog = 60000
  timeout.execution = 600000
```

Это схема параметров, не готовый JSONC.

Используй MCP roots для передачи корня проекта. Не запускай отдельный HTTP-сервер.

Сохраняй другие настройки OpenCode и MCP.

## 9. Создание AGENTS.md

Используй `AGENTS-TEMPLATE.md` исходного комплекта.

Создай или актуализируй корневой `AGENTS.md`:

1. Укажи фактические XML-компоненты и пути.
2. Зафиксируй утверждённые области изменений.
3. Добавь команды проверки проекта.
4. Настрой условную маршрутизацию `.opencode/rules/*.md`.
5. Сохрани непротиворечащие пользовательские правила.
6. Удали неприменимые шаблонные положения и placeholders.

В проекте должен быть только AGENTS.md, шаблон `AGENTS-TEMPLATE.md` Не копируй в проект.

## 10. Финальная проверка

Проверяй только применимые компоненты.

| Компонент | Критерий |
|---|---|
| Окружение | Необходимые инструменты доступны |
| XML | Структура, имена, типы, `cf-validate`, `cfe-validate` |
| Skills | Инструкции и скрипты присутствуют |
| Rules/commands | Manifest и SHA-256 совпадают |
| Базы | JSON корректен, ID и aliases уникальны, подключение работает |
| YAxUnit | Расширения, свойства, alias `yaxunit-test` |
| Git | Исключены секреты и вложенные репозитории |
| MCP | `opencode mcp list` показывает `connected`; `document_symbols` и `analyze_file` выполняются на BSL-файле |
| AGENTS.md | Корректные пути, маршрутизация, отсутствие placeholders |
| Рабочий каталог | Временные файлы удалены, изменения ожидаемые |

### Первый коммит

Допустим только:
- в репозитории, созданном текущим запуском;
- в существующем репозитории без истории, если разрешение получено в разделе 3.

Перед коммитом проверь `git status --short`, состав индекса, отсутствие секретов, `user.name` и `user.email`.

```bash
git add .
git commit -m "init commit"
```

В репозитории с историей автоматический коммит не выполняй.
