# Тестирование

- Тесты выполняются только по явному запросу пользователя.
- Серверная бизнес-логика — существующий YAxUnit и `/yaxunit-test` по корневому `AGENTS.md`.
- UI — загрузить skill `web-test` при существующей публикации и разрешённой dev/test базе.
- Тест сначала фиксирует предусловия, шаги, ожидаемый результат и границы тестовых данных.
- Нулевое число обнаруженных тестов, старый отчёт, ошибка setup/teardown и неизвестный результат не являются успехом.
- Не повторять запись/проведение после таймаута, пока фактическое состояние не установлено.
- Сохранять логи и свежие артефакты запуска; не включать пароль и персональные данные в отчёт.

## Тесты YAxUnit

Сначала изучить стиль существующих тестов. Для новых использовать:

- модуль: `[ПрефиксТипа_]ИмяОбъекта[_СуффиксМодуля]`;
- набор: `ВидМетаданных ИмяОбъекта.[ВидМодуля.] Метод()`;
- тест: `Метод_Сценарий`;
- представление: `Метод(). Описание сценария`.

Использовать техническое имя объекта и создавать набор даже для одного теста. Для сценария фиксировать предусловия, вход, действие и ожидаемый результат. Справка: <https://bia-technologies.github.io/yaxunit/docs/cook-book/test-naming>.

## Запуск YAxUnit

Перед запуском:

1. Загрузить skill `db-cfe-admin` и выполнить операцию `list`, чтобы получить список расширений.
2. Проверить, что `YAxUnit` и `tests` активны, а свойства «Безопасный режим», «Защита от опасных действий» и «Использовать основные роли для всех пользователей» отключены.
3. Включённый безопасный режим или защиту от опасных действий отключить через `db-cfe-admin set-properties`. Свойство «Использовать основные роли для всех пользователей» изменять этим skill только при наличии соответствующего параметра в установленной версии его API; иначе запросить ручное отключение и не запускать тесты до подтверждения.
4. Отсутствующие расширения загрузить в порядке `YAxUnit` → `tests`, применить, загрузив skill `db-update`, затем загрузить skill `db-cfe-admin` и выполнить операцию `check`.
5. Перед явно запрошенным `/yaxunit-test` синхронизировать изменённые исходники `tests` с базой без повторного подтверждения, если точный alias `yaxunit-test` назначен по корневому `AGENTS.md`.

Для каждого запуска создать новый каталог `build/yaxunit/runs/<timestamp>-<short-id>/` с `config.json`, `exit-code.txt`, `report.xml` и `tests.log`. Загрузить skill `db-run` и запустить с `-CParam "RunUnitTests=<absolute-config-path>"`.

Команда запуска из skill `db-run` завершается раньше тестов и не определяет их результат. Успех подтверждают только свежий `exit-code.txt` со значением `0`, корректный jUnit без `failures`/`errors` и ожидаемое ненулевое число тестов. При таймауте проверить лог и процесс текущего запуска, не запускать второй прогон и не завершать чужие процессы.

Формат конфигурации: <https://bia-technologies.github.io/yaxunit/docs/getting-started/run/configuration>.

Структурное управление тонким клиентом без веб-публикации текущим набором не поддерживается.
