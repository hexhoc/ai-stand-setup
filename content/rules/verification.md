# Проверка изменений

Проверяется последнее сохранённое состояние артефакта. Любая последующая содержательная правка делает относящийся к ней результат проверки устаревшим. Не повторять одну и ту же проверку на неизменённом содержимом без новой причины.

## BSL

Для каждого изменённого `.bsl` после последней правки:

1. вызвать `analyze_file`;
2. исправить ошибки и относящиеся к изменению существенные диагностики;
3. повторить один раз после исправления;
4. проверить литералы `\t`, `\n`, `\r` по `.opencode/rules/coding-standards.md`;
5. для изменённого экспортного метода использовать `find_references` и при необходимости `call_hierarchy`.

`analyze_file` подтверждает диагностики BSL Language Server, но не бизнес-логику, фактические данные или полную применимость конфигурации.

Анализ влияния выполнять также при переименовании или удалении метода, изменении наблюдаемого поведения экспортного API, подписки на событие, регламентного/фонового задания, RLS и транзакционного пути. Проверить прямые, строковые и платформенные точки вызова; отсутствие семантического инструмента отметить как ограничение.

## XML и метаданные

- загружать профильный skill проверки: `meta-validate`, `form-validate`, `role-validate`, `skd-validate`, `cfe-validate`, `cf-validate` и т.п.;
- после изменения расширения использовать основную конфигурацию при проверке;
- не считать визуально корректный XML прошедшим проверку;
- проверять регистрацию добавленного/удалённого объекта в родительских XML.
- после любой последующей XML-правки повторить профильную проверку изменённого файла;
- для формы отдельно различать корректность XML, загрузку формы платформой и работоспособность пользовательского сценария.

## Поведение

YAxUnit выполнять, а skill `web-test` загружать и применять только по явному запросу пользователя и только на однозначно выбранной dev/test базе. Для исправления ошибки повторить исходный сценарий после правки, если пользователь разрешил соответствующую runtime-проверку. Статическая проверка не является runtime-тестом. Невыполнимый критерий остаётся `не проверено`.

## Отчёт

Для каждой проверки указать инструмент, артефакт и результат `passed` / `failed` / `not run — причина`. Результат относится только к проверенному файлу/конфигурации и состоянию после последней правки. Не использовать формулировку «всё проверено», если часть применимых проверок отсутствовала.
