# Структура модулей

Сначала сохранять структуру существующего модуля, если она последовательна и не противоречит правилам проекта. Для нового модуля использовать русские имена регионов в стиле БСП. Английские имена допустимы только в конфигурации, где весь код и регионы уже единообразно оформлены на английском языке.

## Общий модуль

```bsl
#Область ПрограммныйИнтерфейс

#КонецОбласти

#Область СлужебныйПрограммныйИнтерфейс

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

#КонецОбласти
```

- `ПрограммныйИнтерфейс` — экспортные методы.
- `СлужебныйПрограммныйИнтерфейс` — экспортные методы для вызова из других функциональных подсистем этой же конфигурации или библиотеки.
- `СлужебныеПроцедурыИФункции` — неэкспортные вспомогательные методы.

Раздел выбирать по потребителям, а не только по наличию `Экспорт` ([#std455](https://v8std.ru/std/455/), [#std551](https://v8std.ru/std/551/)). Неприменимые пустые регионы не создавать. В публичном интерфейсе библиотеки при необходимости выделять вложенную область `ДляВызоваИзДругихПодсистем` для конкретных документированных потребителей ([#std644](https://v8std.ru/std/644/)).

## Модуль объекта или менеджера

Для нового модуля использовать следующий порядок:

```bsl
#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда

#Область ПрограммныйИнтерфейс

#КонецОбласти

#Область ОбработчикиСобытий

#КонецОбласти

#Область СлужебныйПрограммныйИнтерфейс

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

#КонецОбласти

#КонецЕсли
```

В `ОбработчикиСобытий` размещать платформенные обработчики жизненного цикла, в `ПрограммныйИнтерфейс` — прикладной экспортный API. Внешний препроцессорный блок не добавлять механически в существующий модуль с другой подтверждённой областью компиляции; сначала проверить свойства модуля и фактические контексты вызова.

## Модуль формы

Для новой управляемой формы использовать порядок:

```bsl
#Область ОбработчикиСобытийФормы

#КонецОбласти

#Область ОбработчикиСобытийЭлементовШапкиФормы

#КонецОбласти

#Область ОбработчикиСобытийЭлементовТаблицыФормыИмяТаблицы

#КонецОбласти

#Область ОбработчикиКомандФормы

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

#КонецОбласти
```

Для каждой таблицы формы создавать отдельный регион `ОбработчикиСобытийЭлементовТаблицыФормы<ИмяТаблицы>`. Шаблоны показывают порядок областей; в итоговом модуле оставлять только используемые области, без пустых регионов ([#std455](https://v8std.ru/std/455/)).

## Общие правила

- Регионы внутри процедур и функций запрещены.
- Псевдорегионы из комментариев не использовать.
- Не смешивать обработчики событий, публичный API и служебные методы в одном регионе.
- Директиву компиляции ставить непосредственно перед процедурой или функцией.
- Перед изменением директивы проверять фактических вызывающих и доступность используемых значений в выбранном контексте.
- Не переставлять и не переименовывать существующие регионы без задачи на реструктуризацию модуля.
