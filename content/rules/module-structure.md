# Структура модулей

Сначала сохранять структуру существующего модуля, если она последовательна и не противоречит правилам проекта. Для нового модуля использовать русские имена регионов в стиле БСП. Английские имена допустимы только в конфигурации, где весь код и регионы уже единообразно оформлены на английском языке.

## Общий модуль

```bsl
#Область ПрограммныйИнтерфейс

#КонецОбласти

#Область СлужебныйПрограммныйИнтерфейс

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

#КонецОбласти
```

- `ПрограммныйИнтерфейс` — экспортные методы.
- `СлужебныйПрограммныйИнтерфейс` — экспортные методы для вызова из других функциональных подсистем этой же конфигурации или библиотеки.
- `СлужебныеПроцедурыИФункции` — неэкспортные вспомогательные методы.

Раздел выбирать по потребителям, а не только по наличию `Экспорт` ([#std455](https://v8std.ru/std/455/), [#std551](https://v8std.ru/std/551/)). Неприменимые пустые регионы не создавать. В публичном интерфейсе библиотеки при необходимости выделять вложенную область `ДляВызоваИзДругихПодсистем` для конкретных документированных потребителей ([#std644](https://v8std.ru/std/644/)).

## Модуль объекта или менеджера

Для нового модуля использовать следующий порядок. В модуле объекта перед интерфейсом допустима `ОписаниеПеременных`, в конце — `Инициализация`, только если они действительно нужны. Для менеджера, набора записей и менеджера значения константы эти две области недопустимы (#std455, п. 1.1).

```bsl
#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда

#Область ПрограммныйИнтерфейс

#КонецОбласти

#Область ОбработчикиСобытий

#КонецОбласти

#Область СлужебныйПрограммныйИнтерфейс

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

#КонецОбласти

#КонецЕсли
```

В `ОбработчикиСобытий` размещать платформенные обработчики жизненного цикла, в `ПрограммныйИнтерфейс` — прикладной экспортный API. Внешний препроцессорный блок не добавлять механически в существующий модуль с другой подтверждённой областью компиляции; сначала проверить свойства модуля и фактические контексты вызова.

## Модуль формы

Для новой управляемой формы использовать порядок:

```bsl
#Область ОписаниеПеременных

#КонецОбласти

#Область ОбработчикиСобытийФормы

#КонецОбласти

#Область ОбработчикиСобытийЭлементовШапкиФормы

#КонецОбласти

#Область ОбработчикиСобытийЭлементовТаблицыФормыИмяТаблицы

#КонецОбласти

#Область ОбработчикиКомандФормы

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

#КонецОбласти
```

Для каждой таблицы формы создавать отдельный регион `ОбработчикиСобытийЭлементовТаблицыФормы<ИмяТаблицы>`. Шаблоны показывают порядок областей; в итоговом модуле оставлять только используемые области, без пустых регионов ([#std455](https://v8std.ru/std/455/)).

## Модуль команды

Шаблон #std455, п. 1.7:

```bsl
#Область ОбработчикиСобытий

// ОбработкаКоманды с платформенной сигнатурой этого вида команды.

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

#КонецОбласти
```

## Остальные виды модулей

Порядок ниже конкретизирует общие разделы #std455 для вида модуля. Это не требование создавать все области и не универсальная сигнатура обработчиков: их подтвердить по платформе, метаданным и существующему модулю.

| Модуль | Порядок используемых областей | Особенности |
|---|---|---|
| Набора записей | `ПрограммныйИнтерфейс` → `ОбработчикиСобытий` → `СлужебныйПрограммныйИнтерфейс` → `СлужебныеПроцедурыИФункции` | Шаблон объекта без переменных и инициализации; события набора не заменять событиями объекта. |
| Менеджера значения константы | `ПрограммныйИнтерфейс` → `ОбработчикиСобытий` → `СлужебныеПроцедурыИФункции` | Нет разделов переменных/инициализации; проверить доступный API именно менеджера значения. |
| Сеанса | `ОбработчикиСобытий` → `СлужебныеПроцедурыИФункции` | `УстановкаПараметровСеанса` относится к обработчикам; переменные/инициализация недопустимы. |
| Управляемого или обычного приложения | `ОписаниеПеременных` → `ПрограммныйИнтерфейс` → `ОбработчикиСобытий` → `СлужебныеПроцедурыИФункции` → `Инициализация` | Оставлять только допустимое и необходимое; не переносить события между видами приложения. |
| HTTP-сервиса | `ПрограммныйИнтерфейс` → `СлужебныеПроцедурыИФункции` | Входные обработчики ресурсов сгруппировать в интерфейсе; проверить связь HTTP-метода/шаблона URL с методом модуля. |
| Web-сервиса | `ПрограммныйИнтерфейс` → `СлужебныеПроцедурыИФункции` | Методы операций и их параметры согласовать с метаданными/XDTO, не угадывать экспортность и тип ответа. |

В неглобальном общем модуле разделы переменных и инициализации также запрещены. В глобальном общем модуле допустимость не означает необходимость: избегать скрытой инициализации и состояния. Сверка ограничений выполнена по #std455, п. 1.1, 1.4–1.8; дополнения для сервисов и приложения являются соглашением этого комплекта.

## Общие правила

- Регионы внутри процедур и функций запрещены.
- Псевдорегионы из комментариев не использовать.
- Не смешивать обработчики событий, публичный API и служебные методы в одном регионе.
- Директиву компиляции ставить непосредственно перед процедурой или функцией.
- Перед изменением директивы проверять фактических вызывающих и доступность используемых значений в выбранном контексте.
- Не переставлять и не переименовывать существующие регионы без задачи на реструктуризацию модуля.
