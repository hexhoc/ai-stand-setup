# Роли и права

## Область доступа и изменение ролей

- Определить целевых пользователей, полный набор их ролей, требуемые операции и предметную область доступа. Минимальные разрешения подтверждать сценарием; не выдавать полные права для устранения ошибки доступа (#std689, #std532, #std737). Новую роль проектировать для элементарной функции с учётом принятой в проекте модели доступа.
- Определить владельца роли: основная конфигурация или конкретное расширение. Для расширения проверить основные роли (`DefaultRoles`), ограничения прав на заимствованные объекты и фактические настройки применения расширения; не считать права только основной конфигурации полным описанием доступа.
- Предварительно загрузить соответствующие skills. Прочитать права через `role-info`; для новой роли использовать `role-compile`, для существующей — `role-edit` с сохранением UUID, несвязанных прав, RLS и шаблонов. Пресеты раскрывать и сверять с требуемыми операциями: `@edit` включает удаление и интерактивные операции, а не только изменение.
- После правки сверить итог через `role-info` и проверить результат `role-validate`. Если `role-edit` уже выполнил валидацию последнего состояния, без новой причины её не повторять по `verification.md`.
- Проверить совокупность ролей. Отсутствие разрешения или ограничение в одной роли не доказывает запрет у пользователя: например, роль А ограничивает чтение организацией, но роль Б даёт неограниченное чтение того же объекта.
- Для нового пользовательского объекта проверить подсистемы и командный интерфейс по `metadata.md`. Изменение существующих прав описать как разницу «до/после» и указать затронутые сценарии.
