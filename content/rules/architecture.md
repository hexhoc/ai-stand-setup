# Архитектура 1С

Правила должны быть проверяемы. Невыполнимые или противоречащие задаче правила укажи в итоговом отчёте с причиной.

Для операций с метаданными загружай профильные skills: `meta-*`, `form-*`, `role-*`, `skd-*`, `mxl-*`, `cf-*`, `cfe-*`, `subsystem-*`, `interface-*`, `xdto-*`, `template-add`, `help-add`, `support-edit`.

## 1. Согласование изменений

Спроси до:
- создания объекта метаданных или изменения его структуры;
- перехвата вызываемого метода в расширении;
- Добавления индекса.
- установки `ОбменДанными.Загрузка = Истина` при записи.
- изменения режима совместимости или блокировок.

## 2. Ответственность модулей

| Логика                                                                         | Модуль    |
| ------------------------------------------------------------------------------ | --------- |
| Для экземпляра объекта (Проведение, заполнение, проверка, запись)              | Объекта   |
| Общая для всего типа объекта                                                   | Менеджера |
| Общая для нескольких типов                                                     | Общий     |
| Клиентская логика, Видимость, доступность, оповещения, вызовы серверной логики | Формы     |

Области и экспортные методы — по `module-structure.md`.

В проектах на БСП используй принятые суффиксы общих модулей: `Клиент`, `КлиентСервер`, `ВызовСервера`, `ПовтИсп`, `ПолныеПрава`.

`ПовтИсп` допустим только для данных, неизменных в пределах сеанса или вызова; не используй для изменяемого состояния ИБ (#std724).

## 3. Данные и метаданные

Перед изменением определи:
- основную конфигурацию или расширение — по отсутствию или наличию `ConfigurationExtensionPurpose`;
- объект, состояние поддержки и область записи.

Регистрация, права, подсистемы, интерфейс — по `metadata.md`; проверки — по `verification.md`; СКД — по `reports.md`; печатные формы — по `printing.md`.

### XML

- Не редактируй `ConfigDumpInfo.xml`, не переформатируй весь XML и не переставляй несвязанные узлы.
- UUID создавай профильным инструментом; обеспечивай уникальность во всей конфигурации. Не копируй UUID с XML-фрагментами.
- Не добавляй `LineNumber` в табличную часть: его создаёт платформа.
- Создание и удаление объектов согласуй с родительским XML; ссылки — с точными именами и UUID.

### Тип объекта выбирай по назначению

| Назначение                         | Тип                |
| ---------------------------------- | ------------------ |
| Хозяйственное событие и проведение | Документ           |
| Состояние или настройки            | Регистр сведений   |
| Остатки и обороты                  | Регистр накопления |
| Устойчивая сущность                | Справочник         |
| Закрытый стабильный набор значений | Перечисление       |

При сомнении спроси.

### Структура данных

Регистры:
- Измерения — разрезы учёта; 
- ресурсы — измеряемые значения; реквизиты — дополнительные свойства. Не заменяй часто фильтруемое измерение реквизитом ради удобства (#std477).
- Имя объекта — до 80 символов; синоним обязателен. Составной тип требует обоснования. Не используй неограниченные строки в измерениях и полях поиска, отбора или индексации
- Десятки тысяч строк на объект или данные, используемые отдельно от владельца, храни в регистре.
- Индекс добавляй после согласования; укажи в отчёте конкретный запрос с фильтрацией или соединением по индексируемому полю. Часто фильтруемые измерения размещай первыми (#std791, #std652).

### Имена и типы
  - Имя объекта метаданных не длиннее 80 символов (ограничение платформы), синоним задаётся всегда.
  - Составной тип в реквизите не используй без обоснования.
  - Строки неограниченной длины не используй в измерениях и в полях, по которым ищут, отбирают или индексируют.

## 4. Анти-паттерны

Пороги адаптируй к проекту, например через `.bsl-language-server.json`.

| Признак                                               | Проверка или исправление                                         |
| ----------------------------------------------------- | ---------------------------------------------------------------- |
| Модуль > 3000 строк                                   | Диагностика размера модуля                                       |
| Метод > 100 строк                                     | Диагностика размера метода                                       |
| цикломатическая или когнитивная сложность выше порога | Диагностики BSL LS                                               |
| Вложенность > 3 уровней                               | Диагностика вложенности                                          |
| Повторяющаяся логика в формах                         | Вынести в общий модуль (#std440)                                 |
| Скрытая запись в чтении                               | методы `Получить*`, `Найти*`, `Проверить*` вызывают `Записать()` | 
| Поиск в таблице внутри цикла по другой таблице        | Использовать `Соответствие` (#std452)                            |
| Конкатенация строк в цикле                            | Массив и `СтрСоединить` (#std782)                                |
| `Перейти`                                             | Проверка BSL LS (#std547)                                        |
| Циклические зависимости модулей                       | Ревью графа вызовов                                              |
