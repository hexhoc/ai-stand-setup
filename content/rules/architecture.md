# Архитектура 1С

Каждое правило проверяемо. Если правило нельзя выполнить или оно противоречит задаче, не обходи его молча: опиши причину в итоговом отчёте.

**Источник стандартов.** Ссылки вида `#std783` это номера стандартов разработки 1С. Текст стандарта: `https://v8std.ru/std/<номер>/`. Страница диагностики BSL LS: `https://v8std.ru/diagnostics/bslls/<Имя>/` ведёт к нужному стандарту.

Для операций с метаданными выбирай и загружай соответствующий skill из групп `meta-*`, `form-*`, `role-*`, `skd-*`, `mxl-*`, `cf-*`, `cfe-*`, `subsystem-*`, `interface-*`, `xdto-*`, `template-add`, `help-add`, `support-edit`.

## 1. Границы автономии

**Спрашивай до изменений**
- Новый объект метаданных или изменение структуры существующего (реквизиты, измерения, ресурсы, типы значений).
- Новая подписка на событие, новое регламентное задание.
- Перехват метода в расширении, если метод вызывается часто (проведение, запись, обработчики форм списков).
- Добавление индекса.
- `ОбменДанными.Загрузка = Истина` в коде записи: вызывающий код берёт на себя целостность данных (#std773).
- Изменение режима совместимости или режима блокировок.

## 2. Ответственность и контракты

### 2.1. **Размещай логику по таблице** (#std486, #std469).

| Что | Где |
|---|---|
| Проведение, заполнение, проверка заполнения, запись, методы относящиеся к конкретному объекту типа | модуль объекта |
| Операции без экземпляра: выборки, поиск, создание по параметрам, общие методы для типа | модуль менеджера |
| Логика, общая для нескольких типов | общий модуль |
| Видимость и доступность элементов, оповещения, вызов серверной логики | модуль формы |

  Для проектов на БСП суффиксы общих модулей: `Клиент`, `КлиентСервер`, `ВызовСервера`, `ПовтИсп`, `ПолныеПрава`. Публичные методы лежат в области `ПрограммныйИнтерфейс`, внутренние межмодульные в `СлужебныйПрограммныйИнтерфейс`, остальные в `СлужебныеПроцедурыИФункции` (структура модуля: #std455).

### 2.2. **Не объединяй сущности только из-за совпадающих полей** (#std541).
Сравни четыре вещи: смысл, жизненный цикл, владельца данных, правила изменения. Если отличается любая, сущности остаются раздельными. Вывод запиши в отчёт одной строкой.

### 2.3. **Повторное использование (`ПовтИсп`)** (#std724).
Допустимо только для данных, не меняющихся в рамках сеанса или вызова (справочная информация о метаданных, константы окружения). Данные, зависящие от изменяемого состояния ИБ, через `ПовтИсп` не отдавай.

## 3. Данные и метаданные

Перед изменением определи основную конфигурацию или расширение, объект, состояние поддержки и область записи. Основная конфигурация определяется отсутствием `ConfigurationExtensionPurpose`, расширение — наличием этого элемента. После изменения выполни профильный validator, проверь регистрацию объекта в родительском XML и диагностику созданного BSL.

Для СКД определи источник данных, параметры, вычисляемые поля, ресурсы, варианты и настройки пользователя. Вычисление, влияющее на отбор или группировку больших данных, по возможности выполняй источником, а не постобработкой результата.

### XML-инварианты

- Не редактируй `ConfigDumpInfo.xml`, не переформатируй XML целиком и не меняй порядок несвязанных узлов.
- Не генерируй UUID вручную без профильного инструмента. UUID объектов, реквизитов, табличных частей и элементов должны быть уникальны во всей конфигурации; копирование UUID вместе с XML-фрагментом запрещено.
- Не добавляй стандартный реквизит `LineNumber` в описание табличной части: платформа создаёт его автоматически.
- Для группы страниц формы используется тип `PagesGroupExtInfo`; каждый элемент `Page` должен содержать `<enabled>true</enabled>`, если страница не отключена намеренно.
- Добавленный или удалённый объект должен быть согласован с родительским XML, а ссылка на объект — с точным техническим именем и UUID.
- Успешный разбор XML не заменяет профильную проверку схемы и проверку загрузки платформой.

### 3.1. **Тип объекта выбирай по назначению** (#std683). 
- Документ: хозяйственное событие и проведение. 
- Регистр сведений: состояние или настройки. 
- Регистр накопления: остатки и обороты. 
- Справочник: устойчивая сущность. 
- Перечисление: закрытый стабильный набор значений. 

При сомнении между типами спроси.

### 3.2. **Измерения, ресурсы, реквизиты** (#std477). 
- Измерения описывают разрез учёта 
- ресурсы измеряемые значения 
- реквизиты дополнительные свойства записи. Если по полю есть отбор или соединение в запросах, это измерение. Не переноси часто фильтруемое измерение в реквизит ради удобства.

### 3.3. **Имена и типы** (#std474, #std432, #std728, #std550).
  - Имя объекта метаданных не длиннее 80 символов (ограничение платформы), синоним задаётся всегда.
  - Составной тип в реквизите не используй без обоснования.
  - Строки неограниченной длины не используй в измерениях и в полях, по которым ищут, отбирают или индексируют.

### 3.4. **Табличная часть или регистр.** 
Данные, которых может быть десятки тысяч строк на объект или которые нужны отдельно от владельца, храни в регистре, а не в табличной части.

### 3.5. **Индексы** (#std791, #std652). 

Перед любым добавлением индекса, спрашивай разрешение.

- Индексированию подлежат реквизиты или измерения только если в отчёте указан конкретный запрос, который по нему фильтрует или соединяет. Порядок измерений регистра: сначала самые часто фильтруемые.

## 4. События и фоновые операции

### 4.1. **Что запрещено в обработчике записи и проведения.**
Диалоги с пользователем, обращения к внешним системам, долгие вычисления. Обработчик исполняется внутри транзакции, которую уже открыла платформа; правила транзакций описаны в `coding-standards.md`.

### 4.2. **Фоновое и регламентное задание** (#std540, #std539, #std642).
В проектах на БСП: фон запускай через подсистему длительных операций (`ДлительныеОперации.ВыполнитьВФоне`), регламентные задания описывай средствами подсистемы регламентных заданий. Обязательно в коде задания:
  - Единица работы: порция из N объектов (N константа в модуле), транзакция на порцию.
  - Обработанное помечается (реквизит или регистр), при перезапуске задание продолжает с необработанных.
  - Параллельный запуск того же задания исключён или безопасен (проверка активного задания, блокировка).
  - Ошибки и прогресс пишутся в журнал регистрации с уровнем.
  - Отмена: проверка признака отмены между порциями.

## 5. Анти-паттерны с измеримыми признаками

Пороги настраиваются под проект (например, в `.bsl-language-server.json`).

| Анти-паттерн | Признак | Проверка |
|---|---|---|
| God Module | модуль длиннее 3000 строк | счётчик строк, диагностика размера модуля |
| Длинный метод | метод длиннее 100 строк | диагностика размера метода |
| Высокая сложность | цикломатическая или когнитивная сложность выше порога | диагностики сложности BSL LS |
| Глубокая вложенность | более 3 уровней | диагностика вложенности |
| Запрос в цикле | `Выполнить()` или обращение к реквизиту ссылки через точку в теле цикла (#std436) | ревью, BSL LS (проверь набор диагностик в своей версии) |
| Копирование логики по формам | одинаковые блоки в нескольких формах (#std440) | вынос в общий модуль (2.1) |
| Скрытая запись в чтении | методы `Получить*`, `Найти*`, `Проверить*` вызывают `Записать()` | ревью. Если запись нужна, метод называется `ПолучитьИлиСоздать*` |
| Квадратичный поиск | поиск в таблице значений внутри цикла по другой таблице (#std452) | замена на `Соответствие` |
| Массовая конкатенация строк | склейка в цикле (#std782) | сбор в массив и `СтрСоединить` |
| Оператор `Перейти` | любое использование (#std547) | BSL LS |
| Циклические зависимости | модуль A вызывает B, B вызывает A | ревью графа вызовов |
