## Границы изменений

- Код тестов YAxUnit размещать только в расширении `tests`, не в YAxUnit.
- Исключение — настройка их свойств и синхронизация `tests`.

## Именование

Сначала изучить стиль существующих тестов. Для новых использовать:

- модуль: `[ПрефиксТипа_]ИмяОбъекта[_СуффиксМодуля]`;
- набор: `ВидМетаданных ИмяОбъекта.[ВидМодуля.] Метод()`;
- тест: `Метод_Сценарий`;
- представление: `Метод(). Описание сценария`.

Префикс расширения `tests_` исключается из технических имён тестовых модулей и методов. `ПрефиксТипа_` — согласованный префикс типа тестируемого объекта, а не префикс расширения. Например, для `Документ.Заказ` допустим модуль `Документ_Заказ`, тест `Заполнить_НетТоваров`.

Использовать техническое имя объекта и создавать набор даже для одного теста. Справка: <https://bia-technologies.github.io/yaxunit/docs/cook-book/test-naming>.

## Подготовка и запуск

1. Загрузить skill `db-cfe-admin`, выполнить операцию `list` и проверить наличие/активность расширений.
2. Отсутствующие расширения `YAxUnit` делает дальнейший запуск тестов невозможным. Остановится и сообщить о проблеме.
3. У обоих расширений должны быть отключены «Безопасный режим», «Защита от опасных действий» и «Использовать основные роли для всех пользователей». В границах разрешения применять `db-cfe-admin set-properties` только с поддерживаемыми параметрами и только к этим расширениям. Управление свойствами через `ibcmd` ограничено поддерживаемыми им типами баз. Если свойства нельзя изменить автоматически или разрешения нет — запросить действие/подтверждение, не запускать тесты до готовности.
4. Перед явно запрошенным `/yaxunit-test` синхронизировать изменённые исходники `tests` через `db-load-xml`, применить через `db-update`.
5. Выполнить `db-cfe-admin check` для нужных расширений: применимость и синтаксис. Проверки основной конфигурации эта команда не выполняет.
6. Для каждого прогона создать новый каталог `build/yaxunit/runs/<timestamp>-<short-id>/` с `config.json`, `exit-code.txt`, `report.xml` и `tests.log`. Настроить абсолютные пути; по умолчанию `logging.level = info`. Формат конфигурации: <https://bia-technologies.github.io/yaxunit/docs/getting-started/run/configuration>.
7. Загрузить skill `db-run` и запустить с `-CParam "RunUnitTests=<absolute-config-path>"`, передав согласованный фильтр.
8. Дождаться завершения текущего прогона и проверить свежесть артефактов, `exit-code.txt = 0`, корректный jUnit без `failures`/`errors` и ожидаемое ненулевое число тестов. Команда `db-run` завершается раньше тестов и сама по себе не подтверждает успех.

При таймауте проверить лог и процесс текущего запуска; не запускать второй прогон и не завершать чужие процессы. Результат — по `.opencode/glossary.md` с путями к артефактам.
