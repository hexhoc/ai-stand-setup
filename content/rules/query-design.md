# Запросы 1С

Перед написанием определить требуемые строки, группировку, период и поведение при пустых данных. Выбрать источник по предметному смыслу: неправильная таблица или виртуальная таблица — ошибка проектирования, а не задача оптимизации. Таблицы и поля подтвердить, загрузив skill `meta-info`; для запроса внутри СКД дополнительно загрузить skill `skd-info`.

Обязательный минимум:

- параметры вместо конкатенации значений;
- условия виртуальной таблицы передавать в её параметры, когда это возможно;
- несколько предикатов одного параметра виртуальной таблицы соединять через `И`, а не передавать отдельными аргументами;
- запросы не выполнять в цикле;
- поля и таблицы имеют понятные `КАК`;
- временные таблицы, участвующие в соединениях, индексируются по ключам;
- `ОБЪЕДИНИТЬ ВСЕ` предпочтительнее, если удаление дублей не требуется;
- учитывать `NULL`, составные типы и RLS;
- не применять `РАЗЛИЧНЫЕ` для маскировки ошибочного соединения;
- ограничивать выборку, если нужен только первый/ограниченный результат.
- результат `Запрос.Выполнить()` сохранять в именованную переменную, когда далее создаётся выборка, выгрузка или проверяется пустота;
- временной таблице давать имя по содержимому и использовать единый менеджер временных таблиц для связанных пакетов;

- `СрезПервых` и `СрезПоследних` применять только к периодическим регистрам сведений; периодичность подтвердить по метаданным;
- производные поля виртуальных таблиц (`*Остаток`, `*Оборот`, `*Приход`, `*Расход`) не угадывать: подтвердить имя ресурса и используемую виртуальную таблицу по метаданным или существующему проверенному запросу.

Перенос условия из `ГДЕ` в параметры виртуальной таблицы допустим только при сохранении смысла среза, остатков или оборотов: ранний фильтр может изменить не только производительность, но и результат.

При оптимизации дополнительно проверить N+1 через точку, коррелированные подзапросы, подзапросы в `ВЫБРАТЬ`, поздний фильтр виртуальной таблицы и условия, мешающие индексу. Сохранять состав, количество строк, дубли, итоги, поведение при пустых данных и смысл результата; без измерения не заявлять процент ускорения. `analyze_file` даёт статическую диагностику, но не подтверждает разрешение запроса на конкретной ИБ и корректность результата — без отдельного runtime-сценария эти критерии остаются непроверенными.
