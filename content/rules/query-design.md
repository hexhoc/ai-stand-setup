# Запросы 1С

Перед написанием определить требуемые строки, группировку, период и поведение при пустых данных. Выбрать источник по предметному смыслу: неправильная таблица или виртуальная таблица — ошибка проектирования, а не задача оптимизации. Таблицы и поля подтвердить, загрузив skill `meta-info`; для запроса внутри СКД дополнительно загрузить skill `skd-info`.

## Базовые правила

- Выбирать только используемые поля; свёртку, сортировку и простые вычисления выполнять в запросе. Не усложнять запрос ради переноса всей постобработки в СУБД: несколько простых вариантов могут быть стабильнее одного универсального (#std729).
- Значения передавать параметрами. Динамические имена полей и таблиц параметрами не передаются: заменять заранее обозначенный placeholder в цельном тексте запроса только после проверки имени по разрешённому списку (#std437).
- Текст запроса оформлять многострочно, ключевые слова писать заглавными, полям и источникам задавать понятные псевдонимы через `КАК`.
- `ОБЪЕДИНИТЬ ВСЕ` использовать вместо `ОБЪЕДИНИТЬ`, если удаление дублей не требуется. Не применять `РАЗЛИЧНЫЕ` для маскировки ошибочного соединения.
- Учитывать `NULL`, составные типы и добавляемые RLS соединения. Если нужен ограниченный результат, ограничивать выборку в запросе.

Однотипные данные получать одним запросом через `В`, пакет или `ОБЪЕДИНИТЬ ВСЕ`. Запрос в цикле допустим только когда он нужен для порционной обработки, обращений к виртуальной таблице на разные даты либо подтверждённо быстрее и проще общего запроса (#std436).

Не предполагать объём таблицы по метаданным или тестовой базе. Если выбор между индексом, временной таблицей, порционной обработкой или запросом в цикле зависит от количества строк и надёжной оценки рабочей базы нет, запросить у пользователя ожидаемый порядок объёма: до тысячи, тысячи, сотни тысяч или миллионы строк.

## Запрос по таблице значений

Нельзя сразу выбрать данные из таблицы значений в запросе. Прежде всего ее необходимо поместить во временную таблицу
```bsl
Запрос.Текст = 
"ВЫБРАТЬ
|    ТЗ.Номенклатура
|ПОМЕСТИТЬ ВТ_Данные
|ИЗ
|    &ТаблицаЗначений КАК ТЗ
|;
|ВЫБРАТЬ
|    ВТ_Данные.Номенклатура
|ИЗ
|    ВТ_Данные КАК ВТ_Данные
|ГДЕ
|    ВТ_Данные.Количество > 0";
```

## Условия и индексы

- Основное условие, сильнее всего сокращающее выборку, строить по непрерывному префиксу одного подходящего индекса. Порядок предикатов в тексте запроса значения не имеет (#std652, #std658).
- В основном условии не применять функции, арифметику, отрицание и `<>` к индексируемому полю. Диапазон допустим по последнему используемому полю индекса.
- `ИЛИ` в основном условии допустимо для одного поля, когда выражение эквивалентно `В`. Условия `Поле1 = ... ИЛИ Поле2 = ...` при необходимости разделять через `ОБЪЕДИНИТЬ ВСЕ`, только если это не меняет строки и дубли.

```bsl
// Плохо: функция мешает поиску по индексу даты.
ГДЕ МЕСЯЦ(Документы.Дата) = &Месяц

// Хорошо.
ГДЕ Документы.Дата МЕЖДУ &НачалоПериода И &КонецПериода
```

Добавление индекса или изменение порядка измерений согласовать с пользователем: индекс ускоряет чтение, но замедляет запись и может ухудшить другие запросы.

## Виртуальные таблицы

- Условия по виртуальной таблице передавать в её параметр условия, соединяя предикаты через `И`. Перенос из `ГДЕ` допустим только при сохранении смысла среза, остатков или оборотов: ранний фильтр может изменить результат (#std657).
- В параметре условия использовать простые предикаты по полям самой таблицы. Разыменование через точку, соединения, сложные RLS и подзапросы предварительно выносить во временную таблицу.
- `СрезПервых` и `СрезПоследних` применять только к периодическим регистрам сведений; периодичность подтвердить по метаданным.
- Производные поля (`*Остаток`, `*Оборот`, `*Приход`, `*Расход`) не угадывать: подтвердить ресурс и вид виртуальной таблицы по метаданным или проверенному запросу.

```bsl
// Плохо: после расчёта всей виртуальной таблицы.
РегистрНакопления.Товары.Остатки() КАК Остатки
ГДЕ Остатки.Склад = &Склад

// Хорошо: условие участвует в расчёте виртуальной таблицы.
РегистрНакопления.Товары.Остатки(, Склад = &Склад) КАК Остатки
```

Для текущих остатков самый эффективный вариант возможен, когда дата не задана, разделение итогов выключено, а все измерения виртуальной таблицы участвуют во внешнем `ВЫБРАТЬ` или `ПО` (#std733). Применять это только когда предметный смысл действительно требует текущих остатков.

## Соединения и временные таблицы

- Не соединять напрямую с вложенным запросом и не помещать подзапрос в условие `ПО`. Результат вычисления сначала помещать в именованную временную таблицу, затем соединять с ней (#std655, #std656).
- Вложенные соединения не заменять последовательными механически: они могут возвращать разные строки. Если последовательное соединение не сохраняет смысл, использовать временную таблицу.
- Соединение с виртуальной таблицей работает медленно, выборку из виртуальной таблицы помещать во временную таблицу, затем выполнять соединение уже с временной таблицей
- Во временную таблицу помещать только нужные строки и поля (#std777).
- Большую временную таблицу индексировать по полям `ПО` или по полям справа от `В (...)`. Маленькую таблицу до примерно тысячи строк автоматически не индексировать. При неизвестном объёме сначала запросить оценку у пользователя.
- Для связанных пакетов использовать один менеджер временных таблиц.

```bsl
ВЫБРАТЬ ...
ПОМЕСТИТЬ ЦеныПоНоменклатуре
ИЗ ...
ИНДЕКСИРОВАТЬ ПО Номенклатура;

ВЫБРАТЬ ...
ИЗ Документы КАК Документы
	ЛЕВОЕ СОЕДИНЕНИЕ ЦеныПоНоменклатуре КАК Цены
	ПО Документы.Номенклатура = Цены.Номенклатура
```

`ПОЛНОЕ СОЕДИНЕНИЕ` избегать, особенно для PostgreSQL; обычно его заменяют `ОБЪЕДИНИТЬ ВСЕ` с последующей группировкой. Не заменять механически, если это меняет семантику. Одновременное `ПОЛНОЕ СОЕДИНЕНИЕ` и чтение полей табличных частей недопустимо (#std435).

## Проверка оптимизации

Проверить N+1 через точку, коррелированные подзапросы, подзапросы в `ВЫБРАТЬ`, поздний фильтр виртуальной таблицы и условия, мешающие индексу. Пять-семь таблиц считать сигналом проверить сложность и план выполнения, а не жёстким лимитом (#std729).

Сохранять состав и количество строк, дубли, итоги, пустой результат и предметный смысл. Без измерения на сопоставимых данных не заявлять ускорение. `analyze_file` даёт статическую диагностику, но не подтверждает разрешение запроса на конкретной ИБ и корректность результата; без runtime-сценария эти критерии остаются непроверенными.
