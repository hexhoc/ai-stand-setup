# Транзакции и конкурентность

До изменения определить фактический режим блокировок, владельца транзакции и все пути чтения/записи.

## Явная транзакция

Шаблон относится к управляемому режиму блокировок и операции с ответственным чтением. Ключ блокировки должен охватывать все изменяемые разрезы; пример с одним измерением не является универсальным ключом.

```bsl
НачатьТранзакцию(); // Непосредственно перед Попыткой.
Попытка
	Блокировка = Новый БлокировкаДанных;
	Элемент = Блокировка.Добавить("РегистрНакопления.ТоварыНаСкладах");
	Элемент.УстановитьЗначение("Номенклатура", Номенклатура);
	Элемент.Режим = РежимБлокировкиДанных.Исключительный;
	Блокировка.Заблокировать(); // До ответственного чтения.

	// Чтение и запись.
	ЗафиксироватьТранзакцию();
Исключение
	ОтменитьТранзакцию(); // До любых обращений к базе.
	ВызватьИсключение;
КонецПопытки;
```

Чтение, блокировка и обработка находятся в одной `Попытке`. Исключение не поглощать; журналирование на границе операции — по `coding-standards.md`, без повторов на каждом уровне вызова.

## Платформенная транзакция

- Одиночная запись объекта/набора без ответственного чтения не требует явной транзакции (#std783, п. 1.4).
- Не объявлять все события записи транзакционными автоматически: определить фактическую границу по виду объекта и событию платформы. Метод, предназначенный только для вызова внутри уже открытой транзакции, не открывает свою; предусловие при необходимости проверять через `ТранзакцияАктивна()`.
- Вложенный вызов `НачатьТранзакцию()` не создаёт независимую транзакцию. Ошибка запрещает успешное завершение текущей транзакции; реальная отмена выполняется через `ОтменитьТранзакцию()`. До отмены не обращаться к базе даже за представлением ссылки.

## Ответственное чтение

Ответственным считается чтение, по которому изменяют данные или принимают бизнес-решение (#std648).

- Устанавливать блокировку в транзакции до чтения: исключительную для изменяемых данных, разделяемую для данных, используемых только при принятии решения.
- Не распространять этот механизм автоматически на динамические списки, поиск, обычные отчёты и монопольное обновление ИБ.
- Не блокировать регистр целиком без обоснования; задавать значения измерений (#std659, #std661).
- Порядок захвата ресурсов одинаков во всех путях. Если проект не задаёт иное: объекты метаданных по имени, внутри объекта — ключи по возрастанию. Сравнение ключей и порядок документировать в общем владельце блокировок.

## Длительные и внешние операции

- Внешние вызовы, диалоги и ожидания выполнять вне транзакции; полученный результат фиксировать короткой транзакцией. При неизвестном исходе сначала установить фактическое состояние.
- Для фоновой обработки определить размер порции, транзакцию на порцию, прогресс, повторный запуск и защиту от параллельного изменения. Архитектура задания — по `architecture.md`.
- Проверять конкурирующие пути, соответствие ключей блокировки чтению/записи, отмену при ошибке и повторяемость операции. Статический анализ не доказывает отсутствие взаимоблокировок; результат runtime-проверки указывать отдельно по `.opencode/glossary.md`.
