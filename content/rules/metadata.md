# Метаданные

1. Определить контур (основная конфигурация/расширение), точное техническое имя, версию XML, состояние поддержки, префикс и согласованные границы изменения из `AGENTS.md`.
2. Проанализировать существующий объект/аналог через `meta-info`, корень — через `cf-info`; для расширения проверить заимствования и доступность объекта в точной основной конфигурации.
3. Перед структурным изменением получить согласование, если решение ещё не задано задачей. Создавать/изменять/удалять через `meta-compile`, `meta-edit`, `meta-remove`, для корня — `cf-edit`; заимствования — `cfe-borrow`.
4. Проверить точное имя, UUID, типы, синоним, обработчики и включение в `ChildObjects` родителя. XML-инварианты принадлежат `architecture.md`; не редактировать `ConfigDumpInfo.xml` вручную.
5. Проверить права целевых ролей по маршруту `access-rights.md`, включая новые поля и RLS. Не выдавать полные права автоматически. Если права не нужны/наследуются, обосновать это по фактическим настройкам.
6. Для пользовательского объекта проверить включение в подсистемы через `subsystem-info`, изменение через `subsystem-edit`/`subsystem-compile`, затем `subsystem-validate`. Служебный объект не обязан появляться в интерфейсе; указать решение.
7. Проверить видимость и размещение команд в командном интерфейсе подсистем и групп, учитывая права целевых пользователей; изменение — через `interface-edit`, проверка — через `interface-validate`. Включение в подсистему само по себе не доказывает доступность команды пользователю. По #std737 не использовать ролевую настройку видимости в командном интерфейсе конфигурации, интерфейсе основного раздела и рабочей области начальной страницы; доступ определять правами на соответствующие объекты. Видимость не заменяет авторизацию по `access-rights.md`.
8. При переименовании/удалении проверить запросы, СКД, формы, RLS, функциональные опции, команды, подписки и строковые ссылки по `source-search.md`. Совместимость данных и миграцию согласовать отдельно, если они затронуты.
9. Выполнить `meta-validate` и проверку владельца/корня (`cf-validate` или `cfe-validate` с основной конфигурацией), а также validators затронутых ролей, форм и интерфейса.

В отчёте перечислить регистрацию, права, подсистемы и командный интерфейс с результатом каждого пункта по `.opencode/glossary.md`; для неприменимого пункта указать предметную причину. Загрузку/обновление базы согласовать по `AGENTS.md`.
