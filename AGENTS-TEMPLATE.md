# Project instructions

> Это исходный шаблон комплекта. Используй его содержимое как основу для проектного `AGENTS.md`, не копируя сам `AGENTS-TEMPLATE.md` в целевой проект и не перенося этот вводный абзац. Замени все placeholders фактическими значениями проекта и удали неприменимые пункты. Не добавляй в `AGENTS.md` локальные пути к информационным базам, server/ref, пользователей, пароли или конкретные `databases[].id`.

## Структура проекта

- `<configAlias>/src` — основная конфигурация `<base-name>`.
- `<configAlias>.<ExactExtensionName>/src` — прикладное расширение `<ExactExtensionName>`.
<!-- feature:yaxunit:start -->
- `<configAlias>.YAxUnit/src` — тестовый движок; не изменять его исходники без отдельной задачи.
- `<configAlias>.tests/src` — расширение для тестов проекта.
<!-- feature:yaxunit:end -->
- XML-исходники созданы Конфигуратором 1С, это не EDT-проект.

## Границы изменений

- Основная конфигурация: `<read-only либо разрешено изменение>`.
- Если основная конфигурация read-only, прикладные изменения выполнять в согласованном расширении `<ExactExtensionName>`.
- Правки BSL и добавление методов в существующие модули в рамках согласованной задачи выполнять самостоятельно с проверками по `.opencode/rules/verification.md`.
- До создания или изменения структуры метаданных, добавления индекса, подписки на событие или регламентного задания, изменения режима совместимости или блокировок согласовать решение, если оно ещё не согласовано в задаче.
- Аналогично согласовать перехват часто вызываемого метода в расширении и применение `ОбменДанными.Загрузка = Истина`; ответственность за целостность описана в `.opencode/rules/coding-standards.md`.
- Тесты создавать и запускать только по явному запросу пользователя. Если при запросе создания не указаны сценарии, методы покрытия или количество, сначала уточнить требования; не выбирать состав и число тестов самостоятельно. Общие требования — `.opencode/rules/testing.md`.
- Перед загрузкой конфигурации/расширения в базу получать подтверждение пользователя.
- Не удалять, не сбрасывать и не перезаписывать несвязанные пользовательские изменения.

## Инструменты и правила

- `.opencode/rules` автоматически не загружается. Перед работой полностью прочитать применимые правила по маршрутам ниже и рекурсивно их `depends_on`; объединить несколько маршрутов.
- При отсутствии обязательного файла остановить затронутую операцию, сообщить точный путь и запросить восстановление комплекта. Не реконструировать правила по памяти.
- Блок маршрутов генерируется из frontmatter исходных правил.

- Добавлять маршруты по всем затронутым артефактам: например, реквизит и форма → метаданные + форма + XML; изменение обработчика формы → форма + BSL; создание метода → дополнительно структура модуля; запись/проведение → дополнительно транзакции.
- Для XML, форм, метаданных, расширений и базы сначала загружать подходящий project skill из `.opencode/skills`. Для API БСП — `bsp`; его встроенные справочники подтверждают БСП 3.1.11, другую версию сверять с соответствующими источниками.
- Для ревью использовать subagent `onec-reviewer`, передав точный scope/diff и контекст проекта; подготовку diff и регистрацию рабочей папки MCP выполняет основной агент. Не запускать дополнительное ревью без запроса.
- Статусы и серьёзность замечаний определяет `.opencode/glossary.md`.

## Локальный реестр информационных баз

- Все `db-*` skills используют локальный `.v8-project.json`.
- Если файла нет, восстановить его через `db-list` и запросить недостающие локальные реквизиты.
- Не выполнять DB-команды с placeholders, повторными `databases[].id` или неоднозначным выбором базы.
- Не переносить реквизиты, конкретные `databases[].id` и индивидуальные aliases в отслеживаемые файлы.
