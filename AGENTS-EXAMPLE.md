# Project instructions

> Это исходный шаблон комплекта. Используй его содержимое как основу для проектного `AGENTS.md`, не копируя сам `AGENTS-EXAMPLE.md` в целевой проект и не перенося этот вводный абзац. Замени все placeholders фактическими значениями проекта и удали неприменимые пункты. Не добавляй в `AGENTS.md` локальные пути к информационным базам, server/ref, пользователей, пароли или конкретные `databases[].id`.

## Структура проекта

- `<configAlias>/src` — основная конфигурация `<base-name>`.
- `<configAlias>.<ExactExtensionName>/src` — прикладное расширение `<ExactExtensionName>`.
- `<configAlias>.YAxUnit/src` — тестовый движок; не изменять его исходники без отдельной задачи.
- `<configAlias>.tests/src` — расширение для тестов проекта.
- XML-исходники созданы Конфигуратором 1С, это не EDT-проект.

## Границы изменений

- Основная конфигурация: `<read-only либо разрешено изменение>`.
- Если основная конфигурация read-only, прикладные изменения выполнять в согласованном расширении `<ExactExtensionName>`.
- Тесты писать только по явному запросу пользователя и только в расширении `tests`, а не в YAxUnit, следуя `.opencode/rules/testing.md`. Если пользователь не указал состав и количество тестов либо методы, которые должны быть покрыты, сначала уточнить эти требования; не выбирать их самостоятельно.
- Не редактировать `ConfigDumpInfo.xml` вручную.
- Не менять данные информационной базы без явного запроса пользователя.
- Перед загрузкой конфигурации или расширения в базу получать подтверждение пользователя, кроме заранее разрешённого восстановления YAxUnit/tests по правилам ниже.
- Не удалять, не сбрасывать и не перезаписывать несвязанные пользовательские изменения.

## Инструменты и правила

- Каталог `.opencode/rules` автоматически не загружается. Перед работой полностью прочитать только правила, применимые к задаче по маршрутам ниже. Если задача соответствует нескольким маршрутам, объединить их; остальные правила не загружать.
- Поиск исходников или анализ влияния изменения — `.opencode/rules/source-search.md`.
- Ревью заданного кода, diff или готового архитектурного решения — `.opencode/rules/code-review.md`; дополнительно применять маршруты по виду затронутых артефактов.
- Изменение BSL, XML и метаданных — `.opencode/rules/coding-standards.md` и `.opencode/rules/verification.md`.
- Добавление методов, регионов или изменение структуры модуля — дополнительно `.opencode/rules/module-structure.md`.
- Архитектурное решение, проектирование нового поведения или нового объекта метаданных — `.opencode/rules/architecture.md`.
- Интеграция с внешней системой, HTTP-/Web-сервис, REST/SOAP, очередь, webhook или файловый обмен — `.opencode/rules/integrations.md`.
- Написание или оптимизация запроса — `.opencode/rules/query-design.md`.
- Изменение метаданных или XML — `.opencode/rules/metadata.md`.
- Изменение управляемой формы — `.opencode/rules/forms.md`; для `Form.Module.bsl` также применять маршрут изменения BSL.
- Диагностика ошибки или падающего сценария — `.opencode/rules/systematic-debugging.md`, затем правила по виду затронутого артефакта.
- Создание или запуск тестов — `.opencode/rules/testing.md`; для кода тестов также применять маршрут изменения BSL.
- Для операций с XML, формами, метаданными, расширениями и базой сначала использовать подходящий project skill из `.opencode/skills`.
- Для API БСП загружать skill `bsp`. Его встроенные справочники относятся к БСП 3.1.11; другую версию подтверждать по исходникам соответствующей версии проекта.

## Локальный реестр информационных баз

- Все `db-*` skills используют локальный `.v8-project.json`;
- Если рабочего файла нет, восстановить его через `db-list` по шаблону и запросить недостающие локальные реквизиты.
- Не выполнять DB-команды, пока в рабочем файле остаются placeholders, повторяются `databases[].id` или выбор базы неоднозначен.
- Не переносить локальные реквизиты, `databases[].id`, назначения aliases и индивидуальные aliases в отслеживаемые файлы. Зарезервированное имя `yaxunit-test` допустимо только как общее правило без указания конкретной базы.

## YAxUnit: восстановление и запуск тестов

- Этот раздел применяется, только если проект использует YAxUnit и расширение `tests`.
- Alias `yaxunit-test` должен быть назначен ровно одной подтверждённой dev/test базе; иначе остановиться.
- Назначение alias разрешает без повторного вопроса восстанавливать только `YAxUnit` и `tests`, но не данные, основную конфигурацию или другие расширения.
- Для запуска использовать `/yaxunit-test [фильтр]` и полностью выполнять `.opencode/rules/testing.md`.
